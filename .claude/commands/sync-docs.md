# ドキュメント同期確認 (sync-docs)

引数なしで実行: `/sync-docs`

---

## ステップ1: 変更スコープの把握

1. 最新の `.steering/` ディレクトリを特定する:
   ```bash
   ls -lt .steering/ | head -5
   ```
2. 最新ステアリングディレクトリの `tasklist.md` を読み込み、今回の変更内容を把握する。
3. `git diff HEAD~1 --name-only` で変更ファイル一覧を補足的に確認する。

## ステップ2: ドキュメント同期チェック（サブエージェント起動）

`docs/` 配下の全ドキュメントと変更されたコードの整合性をチェックするため、`doc-reviewer` サブエージェントを起動する:

- subagent_type: "doc-reviewer"
- description: "Docs sync check after code changes"
- prompt:
  ```
  以下のコード変更が行われました。`docs/` 配下の全ドキュメントをチェックし、
  実装と乖離している箇所を特定してください。

  ## 今回の変更内容
  [ステップ1で取得した変更スコープをここに記載]

  ## チェック対象ドキュメント
  - README.md
  - docs/product-requirements.md
  - docs/functional-design.md
  - docs/architecture.md
  - docs/repository-structure.md
  - docs/development-guidelines.md
  - docs/glossary.md

  ## 評価観点
  1. 変更されたファイル・構造・機能がドキュメントに正しく反映されているか
  2. 削除・移動されたファイルへの参照が残っていないか
  3. 新規追加された概念・用語が glossary.md に反映すべきか

  ## 出力形式
  乖離がある場合:
  - ドキュメント名、対象箇所（行番号）、現状の記述、推奨する更新内容

  乖離がない場合:
  - 「同期済み」と明記
  ```

## ステップ3: 結果報告と更新の実施

### 乖離がない場合
「全ドキュメントは最新の実装と同期しています」とユーザーに報告して終了。

### 乖離がある場合

1. 対象ドキュメント・箇所・更新案をユーザーに列挙して報告する。
2. ユーザーの承認を得てから `Edit` ツールで各ドキュメントを更新する。
3. 更新完了後、変更内容のサマリーをユーザーに報告する。

---

## 注意事項

- `/review-docs [path]` が単一ドキュメントの**品質レビュー**を行うのに対し、このコマンドは**実装との同期確認**を目的とする。
- ドキュメントの更新はユーザーの承認後にのみ実施する。
